# Предлагаемый тест одного параметра Wi-Fi

Статус: разрешённый тест выполнен. Исходный Auto восстановлен; постоянное отключение энергосбережения не принято. Первоначальная автоматизация контрольного Auto 315 прервалась из-за ADB; отдельный контроль 317 завершён без новых изменений и переподключений адаптера. Первоначальный согласованный план сохранён в `.harness/evidence/integrated-audio/wifi314-approved-plan.md`.

Результат: выключенное энергосбережение 314 — полный сигнал, 7 потерь очереди, 0 underrun/rebuffer; Auto 317 — полный сигнал, 0 потерь/underrun/rebuffer. Поэтому необходимость отключения энергосбережения не подтверждена. Причину улучшения после переподключений нельзя отделить от перезапуска адаптера, порядка опытов и меняющихся условий сети. Подробности в [исследовании](WIFI-RESEARCH.md).

## Основание

В прогоне 312 большие RTT наблюдались и до самого роутера. Установленный MediaTek MT7922/RZ616 сообщает `Power Saving: Auto`, `LowPowerEnable=1`; допустимый вариант выключения — `0`. Microsoft описывает компромисс энергосбережения и задержки. Это проверяемая версия, а не установленная причина. Драйвер 3.6.2.1434 уже совпадает с версией на странице ASUS FA608PM.

## Границы разрешения

Только существующий адаптер с GUID из `wifi313-adapter-preflight.json`, один параметр `LowPowerEnable`. Временное отключение энергосбережения может увеличить расход батареи; применение требует переподключения Wi-Fi и затронет сеть всех приложений. Драйвер, DNS, Firewall, сертификаты, Windows security, профили сетей, роутер, Bluetooth, диапазон и остальные параметры не меняются. Телефонный микрофон не включается.

## Последовательность

1. Повторно проверить идентичность адаптера, драйвер и исходное значение. Сохранить квитанцию. Проверить, что приложения не используют активный RemonteVoice-сеанс и исходные аудиоустройства восстановлены; штатно закрыть только собственный Host и дождаться guard.
2. A: исходное Auto уже имеет неуспешный прогон 312. Перед B при необходимости повторить A с точно теми же измерителями, не меняя параметры.
3. B: выставить `LowPowerEnable=0` через подготовленный `wifi313_power_setting.ps1 -Action DisablePowerSave -ApprovedTest`, затем перезапустить только этот адаптер. Возможен краткий обрыв сети и необходимость прав администратора. Убедиться в реальном восстановлении адреса и маршрута.
4. Запустить тот же Host/APK, синтетический сигнал 240 секунд и два фоновых интервала по 120 секунд, одинаковые ICMP-наблюдатели и проверку Wi-Fi lock. Сохранить счётчики потерь, underrun, rebuffer, интервалы доставки и отправки. При отказе сначала подтвердить возврат устройств Windows, затем завершить только свои тестовые процессы.
5. A повторно: закрыть собственный Host, выполнить `wifi313_power_setting.ps1 -Action RestoreAuto -ApprovedTest`, дождаться переподключения и проверить исходное значение `1`. Повторить тот же сценарий. В штатном завершении и при любой ошибке конечное состояние — Auto, исходные роли аудио/mute и обычный Host.

## Критерий

Нужен повторяемый результат при изменении только одного параметра: успешный полный B и повторное проявление проблемы в Auto. Один успешный B недостаточен для объявления причины или постоянного изменения системы. Предыдущие USB-прогоны остаются отдельным контролем; ICMP не заменяет аудиотест и не доказывает акустическую задержку.

## Восстановление и прерывание

Подготовленный скрипт проверяет GUID/версию и отсутствие Host, записывает намерение до изменения, затем проверяет новое значение. При ошибке применения B он пытается вернуть исходный Auto. Успешный B оставляет `0` только на время измерения; управляющий тест должен вызывать RestoreAuto в finally. Принудительное завершение самого управляющего процесса не гарантирует finally: перед повторной попыткой нужно прочитать квитанцию и фактическое значение, при необходимости выполнить RestoreAuto. Задачи планировщика и службы для отката не создаются.

После восстановления отдельно проверяются реальные значения настройки и маршрута, EXE/APK, отсутствие тестовых процессов, все шесть ролей Windows и исходный mute. Логи содержат только собственные адреса LAN и численные диагностические данные; пароли, SSID, MAC, PCM и пиксели не собираются.
