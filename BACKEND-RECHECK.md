## Исправление диагностики Windows Firewall

Прежнее заключение о Block TCP/UDP было ошибочным: числовое значение `Action=2` в выводе PowerShell означает **Allow**. Повторная проверка Windows PowerShell 5.1 и netsh подтвердила семантику. Поэтому прежний неудачный ConnectException не объяснён Firewall и не считается исправленной продуктовой ошибкой.

По явному разрешению владельца применено узкое правило для этого EXE: **TCP 8765, LocalSubnet, Private/Public, без edge traversal**. Прежнее широкое TCP Allow отключено; UDP Allow и включённый Firewall сохранены. Фактические правила проверены; receipt и независимая проверка — `.harness/evidence/backend-ui/firewall-receipt.json` и `firewall-verified.json`. Повторно применять скрипт не нужно.

Для публичной поставки нужен постоянный путь установки и явный этап настройки локального доступа. Разные тестовые каталоги сборок создают разные идентичности приложения для firewall. Перенос EXE ради обхода существующего Block не выполнялся.
