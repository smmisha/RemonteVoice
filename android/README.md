# RemoteVoice для Android

Нативный клиент для существующего Windows Host: микрофон телефона передаётся в виртуальный микрофон Windows, звук ноутбука возвращается в наушники телефона. Оба устройства подключаются к одной Wi-Fi сети. Одновременно работает один телефон — Android либо iPhone.

## Первая установка

Требуется Android 8.0 или новее. Текущий APK для личной проверки: `preview/RemoteVoice-Android-0.1.16-debug.apk`. Это тестовая сборка, не публикация в Google Play. Исторические проверки слышимости и микрофона описаны выше; длительная речь, глубокий сон и качество текущей пары остаются открытыми.

1. Открой APK на Android и разреши установку для выбранного приложения, если система запросит. Либо установи через `adb install -r` на самостоятельно разрешённое USB-устройство.
2. Запусти Windows Host по инструкции в корневом README. Выбери две **разные** виртуальные аудиопары: системный звук на телефон и микрофон телефона в Windows.
3. Нажми **Новое сопряжение** в Host. На Android выбери **Сканировать QR-код**, разреши камеру, отсканируй QR на ноутбуке. Альтернатива — вставить полную ссылку `remotevoice://pair?...`.
4. Нажми **Подключиться**. При первом сопряжении микрофон выключен. Разрешение на микрофон запрашивается только после нажатия **Включить микрофон**.
5. Подключи наушники, чтобы звук ноутбука не попадал обратно в микрофон телефона. В программе звонков выбери сторону записи второй виртуальной пары.
6. Выключение микрофона оставляет звук ноутбука включённым. **Отключиться** останавливает весь сеанс. У активного сеанса есть системное уведомление.

Для повторного подключения оставь поле ссылки пустым и нажми **Подключиться**: используется сохранённый ключ. После нового сопряжения на Host или замены сертификата отсканируй новый QR. При потере сети автоматического включения микрофона и автоматического переподключения нет.

В обновлённом Windows Host выбери виртуальный вывод Windows и физические динамики/наушники для возврата. При разрыве, ошибке и остановке Host возвращает управляемые роли вывода на физический выход; обычный mute сохраняет звук телефона. Ручной выбор другого выхода не перезаписывается. Обновлённый Host запущен; возврат подтверждён нативным чтением и пользователем после отключения Android. Драйверы виртуального аудио APK не устанавливает.

По отдельному запросу добавлен выбор физического микрофона ноутбука: Host заглушает его на весь сеанс и восстанавливает прежнее состояние при разрыве. Обычный mute телефона не включает микрофон ноутбука. Эта функция меняет только Windows Host; для неё APK обновлять не требуется. Mute на сеанс и последующее восстановление подтверждены нативным чтением. Дополнительно устройство записи Windows возвращается с B2 на физический микрофон; пользователь подтвердил его работу после отключения.

## Просмотр экрана ноутбука

Обновлённые Host и APK добавляют отдельный блок **Показать экран ноутбука**. В Host сначала включите **Разрешить просмотр основного экрана с телефона**, затем откройте блок в подключённом Android. Передаётся весь основной экран с видимыми окнами: detail — до 1920×1200, прежний preview — до 960×540, частота — до двух обновлений в секунду. Кнопка **На весь экран** открывает защищённое окно; щипок, перемещение и двойное нажатие управляют масштабом. Host показывает индикатор передачи; галочка выключена при каждом запуске приложения Host.

Back из полноэкранного окна возвращает встроенный просмотр. Кнопка скрытия, уход Android в фон, разрыв сеанса и снятие галочки останавливают просмотр и очищают картинку. Возврат в приложение не открывает его автоматически. Ошибка экрана показывается отдельно от аудио. Изображения не сохраняются в файлы, постоянный кэш или облако; управление ноутбуком с телефона в эту функцию не входит.

На Android 0.1.16 физическая проверка HD-кадра и lifecycle прошла без отладчика: Back сохранил встроенный просмотр и аудио, Home очистил просмотр и сохранил аудио. После отключения Windows вернула физические устройства и исходный mute за 0,505 с. Качество аудио с просмотром не принято; читаемость и отсутствие слышимого треска требуют оценки владельца. Микрофон автоматически не включался, звук и пиксели не сохранялись.

## Сборка на Windows

Нужен JDK 17. Скрипт готовит Gradle 8.13, Android SDK platform 36, Build Tools 35.0.0 и platform-tools в `.tools/` этого проекта. Архивы скачиваются с официальных серверов, сверяются с контрольными суммами. Android Studio не требуется.

```powershell
./android/scripts/setup-tools.ps1
./android/scripts/build.ps1
```

Сборка запускает `assembleDebug`, `testDebugUnitTest`, `lintDebug`, копирует APK в `preview/` и печатает SHA-256. Кэш, SDK и debug-ключ исключены из Git. Не удаляй debug-ключ, если нужны обновления той же установленной тестовой сборки: новый ключ потребует удаления старого приложения и нового сопряжения.

## Подпись и поставка для пользователей

Личный debug APK сохраняет пакет `dev.remotevoice.android.debug` и существующий локальный ключ. Публичный release использует отдельный пакет `dev.remotevoice.android`. Он не выдаётся за обновление установленного debug-приложения; перенос сопряжения между этими пакетами не реализован. Для обновлений одного release-пакета нужны согласованные версия и сертификат подписи. [Правила Android](https://developer.android.com/studio/publish/app-signing).

По умолчанию GitHub Actions выполняет тесты и lint, собирает **неподписанный release** и публикует `RemoteVoice-Android-unsigned-release-not-installable` с `signing-manifest.json`. Такой APK нельзя установить: это артефакт сборки для проверки, не готовое обновление. CI больше не распространяет APK со случайным ключом нового hosted runner. Все PR и fork идут только этим путём.

Подписанный кандидат включается отдельно для основного репозитория и его default branch: repository variable `REMOTEVOICE_ANDROID_RELEASE_ENABLED=true`, environment `android-release` с настроенной защитой и подтверждённой политикой доступа. В environment задаются Secrets:

- `REMOTEVOICE_ANDROID_KEYSTORE_B64` — Base64 одного постоянного keystore владельца;
- `REMOTEVOICE_ANDROID_STORE_PASSWORD`;
- `REMOTEVOICE_ANDROID_KEY_ALIAS`;
- `REMOTEVOICE_ANDROID_KEY_PASSWORD`.

Публичная variable `REMOTEVOICE_ANDROID_RELEASE_CERT_SHA256` содержит ожидаемый SHA-256 сертификата. Gradle сверяет его с сертификатом keystore до release-сборки; скрипт `scripts/signing-manifest.ps1` повторно проверяет **подпись готового APK** и отклоняет несовпадение. В артефакт входят подписанный release-кандидат и manifest с SHA-256 APK и публичным отпечатком сертификата. Пароли и ключ передаются через environment и временный файл, без значений в аргументах команд. Keystore удаляется из временного каталога CI; кэш подписывающего job выключен. [GitHub Actions Secrets](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-secrets).

Без Secrets остаётся только неподписанный артефакт. Частично заданная конфигурация, неверный keystore и несовпадение отпечатка останавливают подписывающий job. Автоматической генерации запасного release-ключа нет. Для явно разрешённой локальной release-сборки Gradle читает только следующие environment variables: `REMOTEVOICE_RELEASE_STORE_FILE`, `REMOTEVOICE_RELEASE_STORE_PASSWORD`, `REMOTEVOICE_RELEASE_KEY_ALIAS`, `REMOTEVOICE_RELEASE_KEY_PASSWORD`, `REMOTEVOICE_RELEASE_CERT_SHA256`. Проверка manifest выполняется PowerShell 7; она не подписывает APK и не читает закрытый ключ.

**Перед публичным выпуском:** владелец должен выбрать и отдельно сохранить постоянную signing identity, настроить защищённый CI и подтвердить две чистые подписанные сборки с одинаковым сертификатом, затем обновление на телефоне без удаления и потери данных. Здесь ключ не создан, локальные закрытые ключи не читались, Secrets на GitHub не установлены, настоящие release signing/CI/update не выполнены. Публикация в Google Play и выбор Play App Signing остаются отдельным этапом.

## Данные и ограничения

- Только TLS WebSocket к приватному IPv4; отпечаток сертификата берётся из QR, а не из сети при подключении. Переадресация и системный HTTP-прокси не используются.
- PIN нужен для первого подключения. Сохранённый токен шифруется AES-GCM ключом Android Keystore; открытого файлового запасного хранилища нет. Резервное копирование приложения выключено.
- Аудио обрабатывается короткими буферами в памяти, не сохраняется и не уходит в облако.
- Фоновые ограничения конкретных телефонов, Bluetooth, системные звонки, блокировка экрана и реальная задержка требуют проверки на устройстве. Компонентные тесты их не подтверждают.
- Android не требует Apple Account, AltStore, iCloud или LocalSign для установки этого APK.

## Эхо и другие подключения

После перезапуска Voicemeeter обнаружен обратный маршрут AUX → B1. Маршруты разделены: VAIO → B1, AUX → B2; пользователь подтвердил исчезновение повтора голоса в динамике телефона. Host теперь настраивает эту стандартную пару при запуске. Акустическое эхо от громкого динамика и других приложений проверяется отдельно.

Варианты USB-модема, hotspot, Ethernet и Bluetooth описаны в [CONNECTIONS.md](../CONNECTIONS.md). USB/IP сохраняет протокол; Bluetooth требует сжатого аудио и отдельной разработки. Эти дополнительные каналы ещё не проверены на телефоне.

Исходники следующих кандидатов Windows 0.1.13 / Android 0.1.21 содержат защиту ожидания готовности звука и исправление потерь допустимой пачки микрофонных пакетов; 360 Python-проверок прошли. Кандидаты ещё не установлены. Подробности — в PLAYBACK-VIEWER.md.
