# RemonteVoice

**Установлены Windows 0.1.40 и Android 0.1.40 (debug); release APK 0.1.40 подписан локальным ключом.** Открывайте ярлык **RemonteVoice** на рабочем столе: сервер находится внутри Windows-приложения, установленный Voicemeeter Banana запускается автоматически. H.264-кодировщик запускается самим Host только на время разрешённого просмотра. Чат для работы приложения не требуется. Первоначальная установка аудиодрайвера и наличие FFmpeg для видеорежима остаются зависимостями этой локальной версии; при отсутствии кодировщика используется JPEG.

## Установка и обновление Windows

`host/installer/` содержит Install/Update/Uninstall скрипты: Install ставит приложение в `%LOCALAPPDATA%\RemoteVoice\app`, создаёт ярлыки и запись удаления; Update заменяет файлы, сохраняя настройки; Uninstall удаляет приложение, ярлыки и запись. Проверены установка, обновление и удаление на тестовой папке. Release-подпись Android включается переменными `REMOTEVOICE_RELEASE_*`; локальный keystore и пароль лежат в `android/keys/` (вне git) — их нужно забэкапить, иначе будущие release-обновления не подпишутся тем же ключом.

Текущая сборка 0.1.40 — `host/build/desktop-043/dist/RemoteVoicePair`; полный пакет 0.1.39 сохранён в `host/build/retained-017-before043/RemoteVoice`. RemoteVoice соединяет iPhone и ноутбук Windows 11 по одной Wi-Fi сети. Микрофон iPhone можно включать и выключать с телефона; для Windows-программ звонков он выглядит как отдельный виртуальный микрофон. Звук Windows передаётся обратно на iPhone и может воспроизводиться в подключённых наушниках.

## Маршрутизация аудио

Нужны две **разные** виртуальные аудиопары, чтобы голос iPhone не попадал в звук, который ноутбук возвращает на телефон:

1. **Windows → iPhone:** направьте системный звук Windows в playback-сторону первой виртуальной пары. В Host выберите её сторону записи.
2. **iPhone → Windows:** выберите playback-сторону второй пары в Host. В Zoom, Teams, Discord или другой программе звонка выберите сторону записи этой пары как микрофон.

В Host дополнительно выберите **вывод Windows для телефона** и **динамики/наушники при отключении**. До подтверждения подключения Host проверяет маршруты обоих направлений и mute. При разрыве, ошибке и остановке возвращаются управляемые роли вывода и записи; отказ одного шага не отменяет попытки восстановления остальных. Обычное выключение микрофона сохраняет воспроизведение на телефоне. Ручной выбор другого устройства сохраняется. Ошибка Windows показывается явно.

Устройствам VB-Audio playback-сторона называется `CABLE Input`, а парная сторона записи — `CABLE Output`. Для двух направлений выберите разные кабели, например `CABLE` и `CABLE-A`. Для аудиопередачи RemoteVoice показывает виртуальные устройства и не позволяет выбрать одну пару для обоих направлений.

В поле **Микрофон ноутбука** выберите физический микрофон, например Realtek. Галочка заглушает его на время соединения и сохраняет прежнее состояние; заранее заглушённый микрофон не включается. Host не записывает этот микрофон. Отдельный процесс восстановления запускается до подключения и после смерти Host возвращает устройства под исключительной блокировкой. Кнопка **Вернуть звук и микрофон на ноутбук** также проверяет оставшийся журнал mute. Завершение всего дерева процессов, сбой ОС или недоступный драйвер требуют отдельного восстановления; успешный возврат при ошибке не заявляется.

RemoteVoice не содержит установщика аудиодрайвера. VB-Audio описывает [VB-CABLE](https://vb-audio.com/Cable/) как виртуальную пару воспроизведения/записи, а дополнительные кабели A+B распространяет отдельно. Установка драйвера требует прав администратора и перезагрузки. Пакет A+B доступен через магазин производителя; вместо него можно выбрать любые уже установленные совместимые виртуальные пары.

## Windows Host

Требования: Windows 11 x64 и Python 3.12 или новее.

В папке проекта создайте виртуальное окружение и установите зависимости:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r host\requirements.txt
```

Запустите Host:

```powershell
Set-Location host
..\.venv\Scripts\python.exe -m remotevoice
```

Выберите приватный Wi-Fi адрес ноутбука, две виртуальные аудиопары, виртуальный системный вывод и физический выход для возврата звука. Для Voicemeeter Banana: запись B1, вывод голоса AUX Input, системный вывод Voicemeeter Input; выход при отключении — динамики Realtek или ваши наушники. Нажмите **Запустить Host**. Если Брандмауэр Windows спросит разрешение, разрешите доступ в домашней частной сети. Host покажет QR-код и одноразовый PIN.

## Если телефон в другой сети

Прямое соединение работает только тогда, когда телефон и ноутбук видят друг друга по IP: облачного релея и интернет-посредника нет.

- **Проще всего** подключить телефон к той же Wi-Fi сети, что и ноутбук.
- **Если телефон в мобильной сети или другом Wi-Fi** включите на ноутбуке «Мобильный хотспот» (Параметры → Сеть и Интернет → Мобильный хотспот), подключите телефон к этой сети и выберите в Host появившийся адрес (обычно `192.168.137.1`). При первом запуске разрешите приложению доступ в брандмауэре Windows для частной сети.
- **Корпоративная сеть с маршрутизацией между подсетями**: выберите адрес адаптера, доступный телефону; TCP-порт 8765 должен быть разрешён брандмауэром.
- VPN-туннель между телефоном и ноутбуком технически возможен, но не поддерживается и не тестируется; интернет-релей не используется.

## Просмотр экрана на Android

В новой версии Android добавлен блок просмотра основного экрана ноутбука. В Windows Host включите **Разрешить просмотр основного экрана с телефона**, подключитесь на Android и нажмите **Показать экран ноутбука**. Host показывает индикатор передачи. Чтобы остановить просмотр, скройте блок на телефоне или снимите галочку в Host; фон и отключение сеанса также останавливают просмотр.

Просмотр передаётся в локальной сети по отдельному защищённому соединению: согласованный режим detail — до 1920×1200, прежний preview — до 960×540, частота — до двух кадров в секунду. На телефоне виден весь основной экран, включая открытые на нём окна. Изображения не сохраняются. В Android 0.1.16 реальный HD-кадр и полноэкранный режим проверены; Back возвращает встроенный просмотр, Home очищает изображение, аудиосеанс при обоих переходах сохраняется. Читаемость и слышимое качество требуют приёмки владельцем.

## iPhone-клиент

Требования: iPhone с iOS 17 или новее. Xcode-сборка выполняется на macOS, в том числе в GitHub Actions; текущая подпись и установка на iPhone ещё не приняты.

1. На Mac установите XcodeGen, откройте папку `ios` в Terminal и выполните `xcodegen generate`.
2. Откройте `ios/RemoteVoice.xcodeproj` в Xcode, выберите команду подписи, подключите iPhone и запустите приложение.
3. Запустите Windows Host. Отсканируйте его QR-код камерой iPhone и откройте ссылку RemoteVoice.
4. Разрешите доступ к локальной сети и подключитесь. Включайте микрофон только когда нужно передать голос в программу звонка.
5. Подключите наушники к iPhone, чтобы приватно слышать ноутбук.

## Сборка и распространение

В `.github/workflows/build.yml` подготовлены проверки и упаковка Windows, сборки iPhone на macOS и 29 отрицательных/положительных endpoint fixtures. Unsigned IPA не устанавливается сам по себе и не является публичным релизом. Подпись, установка и приёмка iPhone учитываются отдельно; прежние попытки через AltServer/другие установщики не доказали успешную установку.

Android CI по умолчанию выдаёт явно помеченный unsigned release. Постоянная release-подпись включается отдельно владельцем; отпечаток проверяется до сборки и по готовому APK. Личная `.debug`-установка имеет отдельный application ID. Конфигурация — в `android/README.md`.

Публичный выпуск предполагает устанавливаемый Windows-компаньон и телефонные приложения. Сначала исправления аудио/сеанса и приёмка длительной работы, затем чистая установка/обновление, постоянные подписи, разрешения и лицензии. Дополнительные функции имеют меньший приоритет. LocalSign остаётся отдельным инструментом; реальная подпись, свой Anisette и автопродление ещё не приняты.

## Приватность и границы

- Аудио передаётся напрямую по локальной сети через TLS. Сертификат Host сверяется с отпечатком в QR-коде.
- Host принимает соединения только на выбранном приватном IPv4-адресе; интернет и облачное реле не используются.
- Аудио обрабатывается короткими буферами в памяти и не записывается в файлы.
- Одновременно сопряжён один iPhone. Новое сопряжение заменяет прежний телефон после подключения.
- Приложение не отвечает на звонки и не управляет Zoom/Teams/Discord. Выбранный локальный микрофон заглушается в Windows на время соединения; аудиозахват с него Host не открывает.
- Для активного сеанса включён режим фонового аудио iOS, чтобы связь могла продолжаться при заблокированном экране. Системные звонки, смена маршрута или разрешений могут прервать звук.
