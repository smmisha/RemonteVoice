# Запуск установленной Windows Sandbox

На рабочем столе создан ярлык **Windows Sandbox (2 ГБ)**. Он открывает
уже установленное приложение Microsoft 0.8.107.0 через его execution alias
`WindowsSandboxRemoteSession.exe`. Запуск выполняет Explorer, поэтому
окно не зависит от времени жизни терминала или Codex.

`Start-Sandbox.ps1` передаёт XML профиля параметру `--wsb`: этот параметр
принимает содержимое XML, а не путь к файлу. Это интерфейс установленной
версии, проверенный на этом ноутбуке; его совместимость с другими версиями
не заявляется. [Официальный CLI Microsoft](https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/windows-sandbox-cli)
используется только для проверки уже работающих сеансов.

Профиль выделяет 2048 МБ RAM и использует программную графику. Сеть,
микрофон, камера, общий буфер обмена и принтеры отключены. Папки ноутбука
по умолчанию не открываются гостю. Новый запуск требует минимум 2560 МиБ
свободной физической памяти и 4096 МиБ свободного commit; работающий чужой
сеанс не закрывается.

Песочницу создаёт и завершает само приложение Microsoft. Постоянного
PowerShell-контроллера больше нет. При закрытии окна нужно подтвердить
штатное предупреждение об удалении временного содержимого песочницы.
Повторное нажатие ярлыка не создаёт второй сеанс. Запись запуска сохраняется
в `.harness/evidence/sandbox-launcher`; `guest_created` подтверждает создание
гостя, а не его последующее завершение.

26 октября 2026 года проверены прямой запуск приложения и запуск через
обновлённый ярлык, видимый рабочий стол, отсутствие второго сеанса при
повторном нажатии и штатное закрытие обоих сеансов. После закрытия список
гостей пуст; GUI и `vmmemWindowsSandbox` отсутствуют. Проверка ярлыка также
подтвердила отсутствие постоянного контроллера. Принудительное завершение
приложения и перезапуск Windows в эту проверку не входили.

Системный `C:\Windows\System32\WindowsSandbox.exe` пока не исправлен.
В двух новых попытках его дочерний GUI завершился с `.NET Runtime` 1026:
`FileNotFoundException` при загрузке `WinRT.Runtime, Version=2.2.0.0`.
Сама DLL присутствует, имеет указанную версию и действительную подпись.
Alias с контекстом установленного пакета запускает тот же GUI успешно.
Это проверенный обход сбоя запуска; точная причина поиска DLL и связь с
первоначальным сообщением COM не доказаны. Переустановка или изменение
системных файлов не выполнялись.

Это инструмент лабораторного запуска. Он не устанавливает драйвер и не
снимает ограничения тестовой подписи или токенов в госте. Исходный
системный ярлык и параметры защиты Windows сохранены.
