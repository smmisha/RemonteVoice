# Обработка данных в прототипе 0.1

Это описание реализованного исходного кода. Полная проверка сетевого поведения
зависимостей и реальной подписи пока не выполнена; приложение не подготовлено
к публичному выпуску.

- Выбранный IPA читается на компьютере. Код iReSign не загружает его на сервер
  издателя или Anisette; библиотека подписи обрабатывает и передаёт приложение
  выбранному iPhone. Этот поток предстоит проверить на исполнении.
- Пароль Apple Account не сохраняется приложением. Поле очищается перед входом;
  пароль и код 2FA обрабатываются в памяти. Сохранение пароля отсутствует.
- По отдельному выбору пользователя техническая сессия Apple Account (SPD,
  `adsid`, email и адрес Anisette) сохраняется в Windows Credential Manager в
  пространстве `dev.remotevoice.iresign.v1`. Данные делятся на части из-за
  ограничения размера записи Credential Manager. Открытого файлового резервного
  пути нет; ошибка хранилища останавливает зависимую операцию подписи, а
  неудачное сохранение сессии не отменяет уже выполненный вход, но сессия не
  переживёт перезапуск. Сохранение по умолчанию выключено, удаляется при выходе
  и кнопкой «Забыть сохранённую сессию». Техническая сессия позволяет получать
  новые токены Apple без пароля, поэтому она защищается системным хранилищем, а
  не файлом. Записи прежнего прототипа LocalSign в пространстве
  `dev.remotevoice.localsign.v1` этой сборкой не читаются; их можно удалить в
  Windows Credential Manager.
- WebView настроен на приватный режим; автозаполнение полей отключено в форме.
  Полный сценарий входа, файлы профиля WebView и фактические потоки данных ещё
  предстоит проверить до использования учётных данных.
- Данные Anisette и сертификаты подписи сохраняются через Windows Credential
  Manager в том же пространстве. Ошибка хранилища останавливает операцию.
- Для Anisette нужен адрес своего сервиса. Удалённый адрес — только HTTPS, без
  имени пользователя, пароля, query или fragment. Локальный сервис допускается
  по HTTP только на loopback (`127.0.0.1`/`localhost`); iReSign не выбирает
  сторонний сервис автоматически. На этом ноутбуке локальный Anisette v3
  запущен в Ubuntu WSL и слушает `127.0.0.1:6969`; его данные лежат в
  `/opt/anisette-v3-data`, журнал — в `/var/log/anisette-v3.log`. Пароль Apple
  Account в Anisette не передаётся. Автозапуск сервиса — отдельный ярлык в
  папке Startup Windows; его можно удалить. У использованного Anisette-сервера
  лицензия не заявлена, поэтому он применяется только локально для личной
  проверки, а не как компонент для распространения.
- Для входа и создания профилей используется библиотека `isideload 0.4.4` и
  сервисы Apple. Полный список фактических назначений, редиректов и передаваемых
  полей пока не подтверждён.
- Список автопродления хранится в `renewal.json` в каталоге данных приложения:
  bundle ID, имя и версия, UDID iPhone, SHA-256 IPA, срок профиля, время попыток
  и фиксированный код результата. Паролей, токенов и текстов ошибок зависимостей
  в файле нет.
- Одобренная копия IPA для продления хранится в `ipa-archive` в каталоге данных
  приложения. Перед каждой попыткой SHA-256 копии сверяется с сохранённым
  значением; изменённая копия отклоняется.
- Автозапуск — отдельный выбор пользователя. Он добавляет только значение
  `iReSign` в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`; удаление
  переключателя удаляет это значение. Приложение не устанавливает службу.
- Приложение не включает файловый журнал событий, аналитику или автообновления.
  Сырые сообщения зависимостей не отправляются через IPC в интерфейс.
- Диагностика `--diagnostics` выводит версию iReSign, доступность защищённого
  хранилища, число/версии найденных устройств и фиксированный код ошибки. UDID,
  имя устройства, Apple Account, пароль и токены в этот вывод не входят.
- `--check-renewal` выводит только настройки, bundle ID, хеш UDID и сроки; сам
  UDID не печатается. `--check-session` выводит только факт наличия сохранённой
  сессии. `--check-session-storage` записывает фиктивную не-Apple сессию в
  отдельное пространство `dev.remotevoice.iresign.v1.selftest`, проверяет
  чтение и удаляет её; реальные токены и основная сессия не затрагиваются.

Самостоятельная сборка позволяет контролировать исходники, но не доказывает
отсутствие ошибок или уязвимостей во всех зависимостях и сервисах.
