# Ночная проверка RemonteVoice — 23 октября 2026

Исторический ночной срез. Последующая перепроверка и новые сборки Windows 0.1.7 / Android 0.1.8 — [BACKEND-RECHECK.md](BACKEND-RECHECK.md).

Текущий локальный результат: **Windows 0.1.6, Android 0.1.7**. Исходники не отправлялись в GitHub. Публичная готовность не заявляется.

## Исправленная причина отказа повторного подключения

В серии до исправления семь соединений завершились нормально, восьмое было отклонено. Журнал Host показал `previous_failure=True` при работающем сервере и действующей блокировке устройств. Детерминированный тест воспроизвёл механизм: `AudioBridge.stop()` отправлял ошибку завершённого потока после `server_ready`, снова устанавливая запрет подготовки следующего сеанса.

Теперь каждый аудиопоток передаёт непрозрачный идентификатор сеанса. Server проверяет его при отправке статуса, а окно повторно проверяет принадлежность при выполнении отложенного callback. Событие завершённого сеанса отбрасывается. Ошибка действующего сеанса по-прежнему восстанавливает устройства; `server_ready` возвращает их до остановки нативных потоков.

Добавлены безопасные диагностические события Android: фиксированная причина закрытия, код WebSocket, класс сетевой ошибки, смена аудиофокуса и счётчики приёма. Произвольная причина закрытия от удалённой стороны, токен и PCM в них не передаются. Тест проверяет также, что ошибка диагностического наблюдателя не мешает закрытию.

## Проверено

- Тест до исправления обнаружил запоздавшую ошибку. После исправления прошли **270 тестов Host**, compileall и **59 JVM-тестов Android**.
- Offline Android debug/release сборки прошли; lint: 0 ошибок, 3 предупреждения. Установленный APK совпадает по SHA-256 с локальным файлом и подписан прежним debug-сертификатом.
- Исправленный исходный Host выдержал 15 повторных подключений; готовый EXE — ещё пять. После каждого проверены физические роли Windows, исходный mute и отсутствие оставшихся аудиопотоков телефона.
- Готовый EXE выдержал 180.856 секунды фонового сеанса Android. Обычное отключение и завершение телефонного процесса вернули устройства.
- EXE: нормальный разрыв — 0.419 с; аварийный разрыв транспорта — 0.566 с; авария Host — 0.429 с. Отдельно сохранён исходный mute=true и восстановлен исходный baseline.
- При настоящем выключении Wi-Fi телефона Windows вернула устройства за 2.985 с. Wi-Fi включён обратно, прежняя сеть и IPv4 подтверждены. Первая последующая проверка соединения получила ConnectException; более поздняя прошла. Причина первого отказа не установлена.
- Аварийный помощник нового пакета прошёл изолированную проверку. Настройки, сопряжение и сертификат сохранены. Итоговые процессы и состояние — `.harness/evidence/overnight/final-state.json` и `final-processes.json`.

Проверки не включали микрофон телефона и не записывали звук. Непрерывная речь и слышимость текущих сборок человеком не подтверждены. Значения времени относятся к этим наблюдениям, не являются гарантированным максимумом.

## Что остаётся открытым

Одиночное отсутствие foreground-флага примерно на 50-й секунде в прежнем тесте не установило причину завершения: затем сам проверочный скрипт остановил приложение. Нельзя автоматически приписывать этот эпизод исправленному дефекту повторного подключения.

Проверка с погашенным экраном длилась 301 секунду, но только 14 наблюдений показали Asleep, после чего телефон проснулся. Это не приёмка пяти минут непрерывного сна или Doze. Длительный микрофон, смена наушников/аудиоустройств, глубокий сон, чистая установка/обновление Windows, подпись для публичного выпуска и iPhone остаются отдельными этапами. Android-редизайн отложен согласно приоритету пользователя.

Некоторые проверочные JSON сохраняют старые строковые метки версий. Идентичность результата определяется реальными хешами APK/EXE, установленной версией и runtime receipt из `verification.json` и `final-state.json`.
