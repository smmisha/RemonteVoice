# Защищённая связь Host ↔ broker без драйвера

Состояние: подготовка к отдельному разрешению владельца. Этот документ не разрешает установку, повышение прав или изменение ACL. Цель — проверить настоящую взаимную проверку процессов на основном Windows, не активируя аудио. Проверка не подтверждает работу драйвера, физическое восстановление маршрутов или готовность продукта.

## Предпосылки и артефакты

- Read-only проверка CHK-173 подтвердила на ноутбуке настоящую Full/Limited пару одного пользователя. До запуска повторно проверить её и отсутствие другого тестового broker.
- Лабораторный пакет: `host/build/driver-pair-012/dist/RemoteVoicePair`; источник режима — `broker_entry.py` / `broker_composition.py`.
- Подготовленный набор: `host/build/host-admission-012/plan.json`, `prepared.json`, `Invoke-HostAdmission.ps1`, пустая папка `reports`. План фиксирует хеш каждого файла и скрипта. Перед согласованием подготовка и Preflight должны завершиться, фактические хеши — попасть в harness.
- Единственная создаваемая системная папка: `C:\Program Files\RemoteVoice-AdmissionLab-012`. Она должна отсутствовать до запуска. EXE и runtime находятся в её дочерней папке `package`; отдельный `owner.json` связывает удаление с UUID операции и SHA-256 плана.
- Никаких драйверов, сертификатов, служб, задач планировщика, автозапуска, firewall, UAC, Defender, boot-настроек или учётных записей не добавляется и не меняется. Рабочий Host и его устройства не переключаются. Нужен один согласованный запуск подготовленного worker с повышением прав; запрос Windows подтверждает пользователь.

## Порядок ограниченной операции

1. Зафиксировать реальные рабочие PID/время запуска Host и guard, свободную RAM и отсутствие целевой папки. Не закрывать чужие приложения. Повторить Preflight под обычным токеном: файл плана, скрипт и все файлы пакета должны совпасть с согласованными хешами.
2. Запустить `Invoke-HostAdmission.ps1 -Action Run -ExpectedPlanHash <проверенный хеш>` с повышением прав. Аргумент хеша берётся из проверенного `prepared.json`, а не из изменённого плана после согласования.
3. Worker создаёт только указанную папку. Её владельцем становится Administrators; SYSTEM/Administrators получают полный доступ, Users — чтение и исполнение. Права существующих Program Files, Windows и пользовательских каталогов не меняются.
4. Скопировать проверенные EXE/runtime/manifest, установить доверенного владельца файлов, заново сверить все хеши. Reparse-объекты, изменённый пакет, существующая целевая папка и неопределённая прошлым запуском ситуация останавливают сценарий.
5. Worker запускает только `RemoteVoiceBroker.exe --lab-muted-only`. Режим сохраняет настоящие проверки manifest/ACL/токенов/образов; создание `DriverMicWriter` и `WindowsDriverMicTransport` запрещено даже при получении команды enable. Через 60 секунд выставляется stop, через 90 секунд зависший процесс принудительно завершается кодом 70. Дополнительно worker удерживает дескриптор своего дочернего процесса и ограничивает ожидание 110 секундами.
6. Основной агент под обычным Limited-токеном запускает скопированный `RemoteVoice.exe --broker-lab-probe --broker-lab-report <новый абсолютный путь вне установки>`. Никаких UI/autostart/synthetic флагов. Клиент выполняет три status и три heartbeat, затем close. Нормальный результат: exit 0, success/cleanup true, sent/captured frames 0, synthetic false.
7. Между двумя успешными проверками штатного клиента проверить отказ неподписанному workspace Python-процессу: открыть известный локальный named pipe и отправить только пустой HELLO. Подтверждённое соединение должно закрыться без успешного ответа. Успех последующего штатного клиента обязателен: отсутствие сервера само по себе не доказывает отказ чужому процессу. Идентификаторы пользователя/сеанса в отчёты не записываются.
8. Дождаться штатного завершения broker. Worker проверяет отсутствие процессов из тестовой папки, повторно проверяет абсолютный путь, отсутствие reparse и метку владельца операции, затем удаляет только эту папку. Отчёты остаются в проекте.
9. Основной агент отдельно подтверждает отсутствие папки и тестовых процессов, прежние рабочие PID/образы и неизменность управляемых аудиосостояний. Повышенный worker и обычные пробы должны закончиться; больше тестов в фоне не остаётся.

## Откат и отказ

- Если ошибка произошла после создания папки, worker пытается выполнить тот же ограниченный откат. Если есть живой процесс, reparse, несовпавшая метка или недоступная идентичность процесса, удаление не выполняется и результат остаётся `cleanup_confirmed=false`.
- Если worker был прерван, сначала прочитать receipt и фактические процессы. Нельзя повторять Run поверх неизвестного исхода. После завершения/остановки только собственного тестового broker допускается `-Action Cleanup` с тем же планом и хешем в рамках согласованного отката.
- Если broker превысил срок, exit 70 или принудительная остановка — провал штатного завершения, даже если каталог удалось удалить. Лабораторный watchdog не объявляет очистку ресурсов подтверждённой.
- Проблема прав или pinning исправляется в исходниках с повторной идентификацией артефактов; политика доступа не ослабляется для получения зелёного результата.

## Доказательства и границы

Сохраняются hash-bound план/receipt, два scalar-отчёта штатного клиента, результат отклонения чужого процесса, PID/создание и exit broker, факт отсутствия оставшихся процессов и папки. Речь, экран, пароли и ключи не записываются. Сценарий не даёт права запускать synthetic probe или устанавливать/подписывать драйвер на ноутбук.

Источник PyInstaller-пакета, полный runtime manifest и ACL проверяются прикладным кодом. Это не независимая аттестация загрузчика до входа в Python и не production-аудит. Сборка неподписанная; допустимость её короткого повышенного запуска должна быть подтверждена владельцем для этого конкретного сценария.
