# RemonteVoice: план проверки и действий

Срез 26 октября 2026. Спецификация: [SPEC.md](SPEC.md). Архитектура: [ARCHITECTURE.md](ARCHITECTURE.md). Очередь: [ROADMAP.md](ROADMAP.md). Этот документ задаёт будущие проверки, а не сообщает об их выполнении. Текущие доказательства — CHK-169/170/171 в `.harness/state.json` и [WINDOWS-AUDIO-INTEGRATION.md](WINDOWS-AUDIO-INTEGRATION.md).

## Цикл работы над дефектом

1. Зафиксировать сборку, среду и исходные состояния. Проверить разрешения, свободную RAM и отсутствие другого теста, владеющего устройствами.
2. Воспроизвести ошибку, отделить наблюдение от предположения; сохранить минимальные технические данные без речи, кадров рабочего стола и секретов.
3. Исправить причину минимальным патчем. Добавить регрессию там, где она проверяет реальный риск.
4. Выполнить целевые тесты и связанную интеграцию; полный набор запускать при достаточном изменении зависимостей, а не после каждой правки документа.
5. Проверить Git diff, собрать новый идентифицированный пакет, подтвердить его исходники и файлы. Прежние артефакты не перезаписывать.
6. Пройти доступную нативную/физическую проверку. Отказ запуска и проверка с подменами имеют собственный статус и не заменяют положительный сквозной тест.
7. Завершить принадлежащие тесту процессы, проверить реальные маршруты/ресурсы, записать результат и следующий шаг в harness. Неисправность возвращает работу к соответствующему слою.

## Матрица обязательных отказов

Для T3/T4 и затем T5 проверяются:

- Штатное отключение телефона и остановка Host.
- Потеря Wi-Fi, закрытие соединения без close-frame, остановка телефонного процесса.
- Задержка/неравномерная доставка при продолжающемся прогрессе; отдельно полная потеря транспорта. Сетевой сбой моделируется локальным тестовым транспортом; глобальная защита Windows для него не меняется.
- Смерть Host, смерть broker, зависание worker и неподтверждённый END.
- Ошибка частичной подготовки устройств, исчезновение/смена endpoint и ручной выбор устройства пользователем.
- Обычный mic mute: телефон продолжает получать системный звук, выбранный локальный микрофон остаётся в управляемом состоянии; disconnect восстанавливает исходное.
- Исходный mute True и False проверяются отдельно. Поздний callback старого сеанса не должен реактивировать маршруты или разрешать микрофон.
- Повторное подключение начинается с выключенным телефонным микрофоном; незавершённая очистка не допускает новый конфликтующий writer.
- Отказ/отзыв экрана прекращает просмотр и очищает поверхности; аудиосеанс остаётся работоспособным, если его собственный тракт исправен.

Для каждого случая сохраняются: ожидаемый исход, время обнаружения, начало восстановления, нативный readback всех трёх ролей render/capture и mute, оставшиеся процессы/дескрипторы, код ошибки. Физическое чтение состояния и фактическое прослушивание — разные поля отчёта.

## Sandbox и настоящий драйвер

Практический ярлык Sandbox 0.8.107.0 проверен с 2 ГБ RAM, созданием одного гостя и обычным закрытием. Исходный системный launcher имеет отдельную неустранённую проблему загрузки DLL. CHK-168 проверил пакет 010 в госте только на корректный отказ неподходящего запуска; CHK-171 проверил пакет 011 локально. Положительный тракт драйвера из этого не следует.

В имеющемся Sandbox наблюдались Default token / отсутствие linked token, включённый Code Integrity и выключенная тестовая подпись. Текущая lab-композиция требует настоящую Full/Limited пару, а пакет драйвера не имеет production-подписи. Подмена идентичности, отключение проверок и повтор прежних отрицательных запусков этот барьер не закрывают.

Ближайшее действие R1 — сформировать допустимый способ положительного теста на основании этих фактов. Если он потребует установки на основной ноутбук или изменения его защиты, сначала готовятся точный пакет, изменения и проверяемый откат; отдельное разрешение относится ко всему конкретному сценарию. Текущая подготовка такого разрешения не даёт. Отменённые VM не создаются и не запускаются. До закрытия барьера продолжается независимая работа T1/T2 и подготовка жизненного цикла компонентов; R2 не объявляется завершённым.

| Исполнитель | Область | Результат | Граница |
| --- | --- | --- | --- |
| Основной агент | Общая интеграция, package identity, живые процессы/маршруты, приёмка, harness | Проверенный общий результат и запись доказательств | Единственный исполнитель, управляющий реальным сеансом и установкой |
| Субагент A | Broker/runtime/guard: гонки, таймауты, восстановление и недостающие тесты | Находки с путями и воспроизведением; затем отдельный согласованный патч | Не управляет физическим аудио и не пишет canonical state |
| Субагент B | Android audio lifecycle, экран и независимость аудио от видео | Матрица сценариев, дефекты с доказательствами; позже Android-патч | Не меняет Host-контракт без согласования; реальным телефоном управляет основной агент |

При переходе к T8 независимый обзор дизайна заменяет завершённое направление; дополнительные параллельные агенты без задачи не создаются. Общий интерфейс согласуется до изменений; файлы распределяются без пересечения. Основной агент проверяет фактические diff и проверки субагентов. Тяжёлые сборки и гостевые/физические прогоны выполняются последовательно, чтобы не искажать измерения и не перегружать 16 ГБ RAM. В рамках подготовки этого документа субагенты не запускались.

## Готовность и остановка

Проверка получает состояния «запланирована», «выполнена с подменами», «нативная», «физическая», «принята пользователем» с конкретной областью. Отдельно хранится pass/fail/skip и причина. Изменение входных исходников или сборки делает зависимые проверки устаревшими.

В реальном сеансе микрофон включается только явным действием пользователя; диагностическая речь не записывается. При необходимости разрешено остановить рабочий RemonteVoice, сначала обеспечив и проверив возврат устройств. Чужие приложения не закрываются для RAM автоматически. При остатке лимита 1% или меньше состояние сохраняется, работа прекращается; новый сброс не разрешён. Исходники и отчёты остаются локальными; подпись, публикация и Store-подача не выполняются этим планом.


## Расширенная история диагностического аудиосеанса

Для целевого длительного прогона задаются только в окружении запуска Host `REMONTEVOICE_AUDIO_TRACE_DIR` и `REMONTEVOICE_AUDIO_TRACE_PACKETS=90000`. Постоянные настройки Windows и обычный запуск не меняются. Без каталога трассировки параметр количества пакетов игнорируется; короткий режим сохраняет прежние6000 строк. Явный предел принимает целое число от1 до90000; ошибочное значение безопасно возвращает короткий режим и помечается `invalid_default`, исходное значение в отчёт не попадает.

Одинаковая ёмкость применяется к packet/native/wait, номера аудиопакетов и формат колонок сохраняются.90000 пакетов — около15 минут при100 пакетах/с; память растёт постепенно и ограничена. Это ограничение по числу пакетов, не обещание полного журнала при сеансе любой длительности. Независимые128 медленных событий и600 TCP-срезов сохраняют прежние пределы. Запись файла по-прежнему выполняется после остановки workers, PCM в отчёт не передаётся.

Новый раздел `trace_retention` содержит выбранный/максимальный предел, причину выбора, первый/последний оставшийся номер, число вытесненных пакетов и `history_complete`. Последнее означает сохранение всех завершённых packet-измерений, а не успешность всего аудиосеанса или наблюдателя. Для сопоставления дополнительно проверяются native/wait counts, одинаковые номера и observer status/ошибки/pending. При усечённой истории отсутствующий пакет не считается доказательством сетевой или иной причины. Старые отсутствующие строки не восстанавливаются.

Регрессия: исходный62067-пакетный562 потерял пять ранних сопоставлений при ёмкости6000. Проверить переход за6000 пакетов, ранние номера10426/40803/41033/42694/48751 при выбранных90000, согласованное вытеснение всех трёх таблиц, безопасный разбор/предел и отсутствие hooks/буферов/I/O по умолчанию. Затем новый идентифицированный билд и10-минутный реальный прогон с явными90000: отсутствие вытеснения и сохранение каждого номера, включая ранние receive events; штатное восстановление6 ролей/mute до cleanup, отключение профиля и нормальный запуск.
